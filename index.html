NyanOS-v1

Nyanos v1
A Hobby Operating System
Developer Yunus Emre Duran
Programming language C and x86 Assembly
Architecture 32-bit x86
Kernel type Monolithic (Educational/Hobby)
Source Code GitHub Repository ↗

Nyanos is a real, working 32-bit x86 kernel. It boots via Multiboot (GRUB or QEMU's built-in loader), sets up its own GDT and IDT, has PS/2 keyboard/mouse/timer drivers, switches VGA into a graphics mode by programming hardware registers directly (no BIOS calls), and runs a small desktop environment with a real window manager, a shell, a text editor, a paint program, and a local document viewer[cite: 1].

It was built and verified to compile and link successfully in a standard environment with gcc -m32, as, and ld (no nasm/qemu/grub required for compilation)[cite: 1]. The Multiboot header was checked byte-for-byte: checksum validates to 0, it sits within the first 8KB of the file, and the ELF entry point lands in the correct loaded segment[cite: 1].

What's real here (and what isn't)

Everything listed below is implemented and does what it says — no stubs pretending to be features[cite: 1]:

  • Real interrupt-driven drivers: keyboard, mouse, and a PIT timer all work through actual hardware IRQs (1, 12, 0), not polling loops[cite: 1].
  • Real graphics: VGA Mode 13h is set up by programming the sequencer / CRTC / graphics controller / attribute controller / DAC registers directly — the same technique real bare-metal OSes use[cite: 1].
  • Real window manager: draggable, closable, focusable, z-ordered windows; a taskbar with per-app buttons; a Start menu[cite: 1].
  • Real shell: typed commands are tokenized and dispatched to real command implementations[cite: 1].
  • Real file storage: an in-memory ("RAM") file system with actual write/read/list/delete operations, shared by the shell, text editor, and document viewer[cite: 1].

One thing is intentionally not real, and it's important to be upfront about it: the "Browser" is a local document viewer, not an internet browser. nyanos has no network driver, no TCP/IP stack, no DNS, no TLS, and no HTML/CSS/JS engine[cite: 1]. Building those from scratch is a multi-year effort even for professional teams[cite: 1]. What the Browser app does do for real: it reads pages from the in-memory file system and renders a tiny, self-invented markup format (heading and bullet lines), with a working address bar, Home button, and Reload button[cite: 1]. It's the honest, functional equivalent of a browser that actually fits inside a hobby kernel[cite: 1].

cat <file>        print a file's contents

paint            open the paint program

How to build and run

On a Linux machine (or WSL), you can build it with[cite: 1]:

sudo apt install build-essential   # gcc, as, ld (with 32-bit multilib)
make

This produces nyanos.elf, a Multiboot-compliant kernel image[cite: 1].

How to run it (QEMU — easiest way)

No GRUB/ISO needed — QEMU can boot multiboot kernels directly[cite: 1]:

sudo apt install qemu-system-x86
make run

Quick Start (No build required!)

If you don't want to build it yourself, you can go to the GitHub repository and download the release files[cite: 1]. Run it instantly using QEMU[cite: 1]:

qemu-system-i386 -cdrom nyanos.iso

This runs qemu-system-i386 -kernel nyanos.elf[cite: 1]. You'll see boot status messages in text mode for a moment, then the screen switches to 320x200 graphics mode and the desktop appears with the About and Terminal windows open[cite: 1]. To use the mouse in the QEMU window, click into the window to grab the mouse (QEMU's status bar tells you how — usually Ctrl+Alt+G releases it)[cite: 1].

How to build a real bootable ISO (optional, via GRUB)

sudo apt install grub-pc-bin xorriso
make iso
qemu-system-i386 -cdrom nyanos.iso

You can dd this ISO onto a real USB stick and boot it on real hardware (BIOS mode) — the kernel doesn't use any BIOS calls after boot (VGA mode switching is done by direct register programming), so it should, in principle, work on real machines too[cite: 1].

Using the desktop

  • Click MENU (bottom-left) to open any app, or SHUT DOWN[cite: 1].
  • Each app also has its own taskbar button; click it to open/focus it, click again while it's focused to close it[cite: 1].
  • Drag windows by their title bar. Click the red square (top-right of a window) to close it[cite: 1].
  • Terminal: click it to focus, then type — it's a real shell (see command list above)[cite: 1].
  • Notepad: click to focus, type to edit, click SAVE to persist to notepad.txt in the file system (readable via cat notepad.txt in the shell), LOAD to reload it, CLR to clear the buffer[cite: 1].
  • Paint: click a palette swatch to pick a color, then click-drag on the canvas to draw. CLR clears the canvas[cite: 1].
  • Browser: click HOME to load the default page, RELD to reload the current page, README to view readme.txt. Use the shell's browser <file> command to load any file you've written[cite: 1].

Deliberately out of scope (ideas for what's next)

This is a real kernel at "educational hobby OS" scale, not a production operating system[cite: 1]. Natural next steps[cite: 1]:

  • Memory management: no physical page allocator or paging yet — everything currently runs in one flat address space[cite: 1].
  • Multitasking: no scheduler; the GUI runs in a single loop (gui_run). The PIT timer driver is already IRQ-driven, so a preemptive scheduler could hook into it fairly easily[cite: 1].
  • Persistent storage: the file system is RAM-only and resets on reboot; a real disk driver (e.g. ATA/IDE) plus an on-disk format (e.g. FAT) would make it persistent[cite: 1].
  • Networking: this is the big one for a "real browser" — a NIC driver, a TCP/IP stack, DNS, TLS, and an HTML/CSS/JS engine[cite: 1].
  • Richer GUI: window resizing, more fonts/sizes, scrollable text areas, a proper cursor-based text editor (the current Notepad only supports append + backspace at the end)[cite: 1].
